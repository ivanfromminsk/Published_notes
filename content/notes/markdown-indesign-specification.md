## Общее

Разработать скрипт `.jsx` для Adobe InDesign, который синхронизирует текстовые фреймы документа с содержимым Markdown-файла. Текст редактируется во внешнем Markdown-файле.

- Каждый текстовый фрейм в индизайне, синхронизируемый со скриптом, должен иметь `Script Label`.
	- Идентификатор должен поддерживать латинские буквы, цифры и подчёркивания.
	- Возможно несколько фреймов с одинаковым идентификатором (тогда действовать с ними как с повторяющимися записями, чтобы в разных местах индизайна появились одинаковый текст)
- Маркдаун
	- Заголовок первого уровня с идентификатором определяет, в какой фрейм попадёт текст `# ANALISYS_01`
	- Содержимое после заголовка относится к указанному идентификатору до следующего заголовка с идентификатором.
	- Заголовки-идентификаторы являются служебными и не должны попадать в текст фрейма.
	- Для отдельных абзацев должна быть предусмотрена возможность переопределить стиль секции.

```
{style=Caption}Подпись к изображению.

{style=Body Copy}Следующий основной абзац.
```

- Директива `{style=...}` относится только к следующему абзацу.
- Название стиля должно соответствовать существующему стилю абзаца InDesign.
- Служебная директива не должна попадать в итоговый текст.
- Если стиль не найден, то применяется стиль по умолчанию без изменений

## Абзацы и пустые строки

1. Один обычный абзац Markdown преобразуется в один абзац InDesign.
2. Переносы строк внутри одного абзаца Markdown не должны автоматически создавать новые абзацы: по умолчанию они объединяются пробелом.

## Поддержка стиля символов
- если в маркдаун применены к тексту Болд `**текст**` — полужирное начертание; или италик `*текст*` — курсивное начертание то к этой части текста в индизайне применяются преднастроенные в индизайн стили символов Markdown Bold и Markdown Italic соответственно
- должна быть возможность применения к тексту других стилей символов которые уже есть в файле индизайн. но в отличие от стиля абзаца применение должно быть возможно гибко к определенному диапозону символов

## При запуске скрипта
- появляются кнопки связать маркдаун файл Позволять выбрать Markdown-файл через стандартный диалог выбора файла.
- Запоминать путь к последнему использованному файлу в метках документа InDesign.
- вторая кнопка для обновления предыдущего файла без необходимости снова выбора его
- Корректно сообщать, если файл перемещён, удалён или недоступен.
- Не перезаписывать исходный Markdown-файл.

## Синхронизация содержимого
- Сравнивать новое содержимое Markdown с текущим содержимым соответствующего фрейма. (выводить рядом в колонках старое и новое содержимое)
- Не менять размеры, положение, поворот и геометрию фреймов.
- Не менять настройки страниц, слоёв и объектов, не относящихся к синхронизации.
- Не удалять и не создавать новые фреймы автоматически.
- Сохранять идентификаторы `Script Label`.
- При этом изменение текста не должно приводить к потере оформления, которое должно сохраняться по правилам проекта.

## Предварительный просмотр изменений
- Перед применением изменений скрипт должен показывать отчёт и запрашивать подтверждение. (выводить рядом в колонках старое и новое содержимое)
- даже при наличии ошибок делать доступной кнопку применить изменения
- Пользователь должен иметь возможность:
1. Просмотреть список изменений.
2. Отменить операцию до применения.
3. Подтвердить обновление.
- отчет с указание информации и на какой странице находится
## Визуальная маркировка фреймов

Необходимо предусмотреть дополнительный инструмент, позволяющий быстро понять, какой фрейм соответствует какому идентификатору.

Предпочтительный вариант — команда включения и выключения служебных меток.

Требования:
- Метки должны располагаться рядом с соответствующими фреймами.
- Метки должны находиться на отдельном служебном слое.
- Слой должен быть непечатаемым.
- Метки не должны попадать в основной текст и не должны участвовать в синхронизации.
- Скрипт должен позволять создавать и удалять метки повторно без накопления дубликатов.
- Генерация меток не должна менять геометрию исходных фреймов.
